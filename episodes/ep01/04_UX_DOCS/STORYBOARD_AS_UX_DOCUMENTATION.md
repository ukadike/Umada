# UMADA EP01 — Storyboard as UX Documentation

## Why the complete board remains visible

The full board is not merely promotional art. It is a compact systems diagram for Episode 1.

It documents:

- mandatory historical anchors;
- audience-choice hubs;
- optional investigative routes;
- convergence points;
- evidence-channel transitions;
- rescue doctrine emergence;
- the closing handoff to Part Two.

## UX role legend

| Role | Meaning |
|---|---|
| Fixed anchor | Locked historical event. Evidence can be examined; outcome cannot be changed. |
| Hub | Choice point opening multiple routes or witness signals. |
| Branch | Optional route that changes knowledge and ledger state. |
| Convergence | Locked event reached through different contexts. |
| Rescue hub | Post-blast choice point for selecting a rescue perspective. |

## Documentation behavior

The UX-documentation screen should:

- show the complete board first;
- provide a frame-by-frame semantic list;
- identify each frame's UX role;
- connect frames to story states;
- display alt text and canon warnings;
- allow filtering without hiding information from assistive technology;
- remain separate from immersive Story Mode.

## Story behavior

The story screen should:

- use clean cropped frame images;
- place narrative and controls in HTML;
- allow route and evidence choices;
- track visited frames;
- generate a witness ledger;
- preserve fixed historical outcomes.
